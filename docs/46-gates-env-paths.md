# 46 — Gates, env flags, three paths

Full detail split out of `CLAUDE.md` to keep that file small. `CLAUDE.md` carries the one-line rules; this file carries the *why* and the exact conditions. Read the relevant row before choosing a gate, touching a transport, or adding a `SLOPDESK_*` flag.

## Gates — which one reaches which path

Clean checkout builds headless with no prerequisite: `swift build`/`swift test` never see libghostty, and reach VideoToolbox / ScreenCaptureKit only as SDK frameworks `Package.swift` links on macOS (the calls are Rust's — `slopdesk-apple-vt`, `slopdesk-apple-sck` — behind `CSlopDeskFFI`); libghostty only in Xcode app targets (`TerminalSurface` seam), built via `ThirdParty/ghostty/build-libghostty.sh` (Zig; never blocks headless core).

Diffs against the last full-green tree, so scope grows until a full run resets it; Package.swift/golden/unattributable paths escalate to full; a partial green never warms the pre-push cache. ### The four `slopdesk-guigate` modes own a `slopdesk-superd` each, and census THAT

A GUI gate starts its own supervisor on `$SLOPDESK_SUPERD_DIR=/tmp/slopdesk-gate-<port>-sd` and `SIGKILL`s it on the way out. Not hygiene — the developer's superd is a `LaunchAgent` holding every live pane on the machine, and sharing it made two gates permanently red on any machine that had run them before: `launch-restore`'s fixture names FIXED pane uuids (its seeded `workspace.json` has to), every gate run ends in `SIGKILL` by design, so the panes stayed supervised and the next run's first dial was answered `refused("pane 1111… is already supervised")` — reported by the gate as "the host spawned 0 shells", which is true and points at the wrong half. Each run also leaked its shells into that daemon (nine were parked there when this was found). A private superd starts with an empty registry, takes its panes down with it, and — the third reason — has a pid the gate KNOWS rather than one it would have to `pgrep` for on a machine with a real one running.

That pid matters because **a pane census is taken of superd, never of hostd**: superd forks and holds every pane (`docs/51` §1), so hostd's children are `slopdesk-screend` and a scattering of transient probes, and the pty count these gates took of hostd was structurally zero against a host whose own log said it had attached three shells. Session-leadership alone is no longer the whole discriminator either, now that the parent is right: a SERVICE pane (`code-server`, `slopdesk-dropd`, `slopdesk-androidd`) is a real pane on a real pty, so `argv[0]`'s login-shell `-` separates the two with no table of service names to keep in step.

## The inner loop — `make quick` after every edit, `make check` before pushing

`check` = `lint build test miri golden check-ios`. `quick` = `ffi lint test-touched golden check-ios`: the same gate with the full suite swapped for the touched-target selection and Miri omitted (a memory audit answers a question only an `unsafe` edit can ask, and the three crates that may write it are each covered by `make lint-rust` and their own differential suites).

It is cheap because nothing in it re-does work whose inputs did not move:

- **`slopdesk-gate ffi`** hashes the shim's sources and every crate reachable from it by a `path = "../…"` edge, plus the header and the script itself. A second run on a warm tree exits in milliseconds; `--check` (in `make lint`) reports staleness without building. Its three slices build CONCURRENTLY, each into its own directory under the shim crate's derived `target/ffi` — separate directories rather than one, because cargo takes an exclusive lock on a target directory and three builds sharing one merely queue. Measured on one edit to a wrapped crate: 70 s serial, 55 s backgrounded onto the shared directory, **14 s** as it stands. The header⇄library symbol check on each slice is two `comm` passes over sorted sets, not 776 `grep -c` sweeps per slice (which cost 20 s and, being substring matches, let a door renamed to a longer name pass).
- **`check-ios.sh`** is stamped as the table row above describes: **0 s** when no iOS-compiled input moved. A Swift edit does move it, and then the gate costs what one xcodebuild plan costs — which is why `quick` runs it CONCURRENTLY with `test-touched`, the other cost a Swift edit pays. Those two share nothing but the SwiftPM lock, and the only thing that lock delays is `golden`.
- **`make lint`** runs its five linters concurrently into per-linter logs, replayed in the declared order once all have finished — ordered output without `--output-sync`, which this repo's make (3.81) does not have. 55 s → **34 s**. It was bounded by the shell ratchet until that became `rust/slopdesk-invariants`; what is left of it is `lint-reach`, four `make -n` expansions and one content stamp. The fourteen repo-wide token bans it used to start as a background Python process are rules in the same crate, and run with the rest of that registry under `lint-invariants`.
- **`test-touched.sh`** selects by dependency closure and escalates to the full suite on any path it cannot attribute — fail-toward-slow.

The one thing to remember: `quick`'s speed is entirely a claim that a stamp is honest. When a verdict looks wrong, `slopdesk-gate ffi --force` / `check-ios.sh --force` re-run unconditionally, and `make check` is always the answer of record.

Ratchets inside `make lint`: `slopdesk-invariants` rules `design-token-leaks` (Slate tokens live in `Sources/SlopDeskSlate/SlateDesign.swift`) and `menu-shortcutless` (no `.keyboardShortcut` in `WorkspaceCommands.swift`), plus the rest of that registry (row above).

SIMD detail: the frame hash is scalar (`rust/slopdesk-video/src/frame_hash.rs`), **not** NEON — only the GF(2⁸) multiply kernel has one, and it lives alone in `rust/slopdesk-gfsimd`, the third `unsafe` crate. Two suites pin it: `rust/slopdesk-gfsimd/tests/differential.rs` for kernel ≡ scalar twin, and the cross-region cases in `rust/slopdesk-video/src/gf256.rs` for the seam the kernel cannot see on its own — a region whose tail straddles a 16-byte chunk.

Hang-safety detail: video unit tests stay pure `SlopDeskVideoProtocol` + controllers — no `SCStream`, `VTCompressionSession`, `VTDecompressionSession` or Metal device. Security detail: there is no app-layer crypto/auth; the replay buffer holds raw bytes and the WireGuard mesh is the boundary.

## Three paths (do not merge)

Separate transport, message set, version (`1` only — no negotiation).

| Path | Notes that bite |
|------|-----------------|
| Terminal (TCP) | Dual `.data` + `.control`; `TCP_NODELAY` on **both**. ReplayBuffer 256 MiB cap, 64 MiB offline gate **pauses PTY drain**; queue gate 64 KiB attached (latency) ↔ 64 MiB detached (budget — agent keeps running while away). Both pauses now travel one hop further: the drain is `slopdesk-superd`'s (`docs/51` §6.5), so a pause is a `pause` verb that stops its reads, the kernel PTY buffer fills, and the shell backpressures — same never-drop mechanism, one process away. Real smoke: `SubprocessE2ETests` (in-memory loopback misses open-order races). |
| GUI video (UDP) | Media socket (1-byte channel tags; recovery has its own tag) + dedicated cursor socket. FEC via `FECScheme` (RS GF(2⁸)). |
| Inspector (TCP) | Read-only; client→host is only `subscribe(fromSeq:)`. Served by `slopdesk-inspectord` on `terminalPort + 1`, dialled directly — hostd relays nothing and, since `docs/54`, holds nothing. |

**Not a fourth path (2):** the Claude Code hook relay is a SEPARATE PROCESS (`~/.claude/hooks/slopdesk-agent`, built from `rust/slopdesk-hook`) that speaks one line-framed record over AF_UNIX to `AgentHookListener` — no FFI, no `SlopDeskProtocol`, no wire version. It is same-machine by construction (the hook runs inside the host's own PTY). ⚠️ It must stay SYNCHRONOUS (ordering is meaning) and must keep BOTH `PreToolUse` and `PostToolUse` — see the CLAUDE.md invariant. `swift build` does not produce it; `make build` stages it beside the host binary, together with the `slopdesk-agenthooks` that installs it — which is where `AgentHooks.locate` looks.

**Not a fourth path:** the Simulators panel speaks a FOREIGN wire (`baguette serve` — HTTP + one websocket, H.264 down / JSON up) to a third-party process, sharing no socket, message set or codec with the three above; `SlopDeskProtocol` never sees a byte of it. Only discovery (metadata verb 21) rides a SlopDesk wire, and it carries an address, not frames. Dialect, traps and fixtures: **`docs/47-simulator-panel.md`** — read it before touching anything under `Sources/SlopDeskPhoneUI/Panel/Simulator`. Gate: `make test-touched` (the whole panel is unit-testable — both runtime seams are injectable, so no test opens a socket or builds a display layer).

**Nor is the Android panel:** a SECOND foreign wire — the host's own bridge relaying `scrcpy-server` v4.1 (H.264 down / touch and key messages up, on ONE full-duplex TCP connection). The relay is not optional: `adb forward` binds 127.0.0.1 only, so a mesh client cannot reach the device socket without it (`adb -a server -H 0.0.0.0` was rejected — machine-wide, and it hands every peer a device shell). Only discovery (metadata verb 22) rides a SlopDesk wire. Dialect, measurements and traps: **`docs/48-android-panel.md`** — read it before touching anything under `Sources/SlopDeskPhoneUI/Panel/Android` or `rust/slopdesk-androidd`. Since 2026-08-12 the relay is that crate — a separate binary held by superd, dialled DIRECTLY by the client, with the Swift original deleted in the same change. hostd only ensures it (verb 22) and never sees a frame. Gates: `make test-touched` for everything pure on both sides, `slopdesk-gate android` for the sockets, `slopdesk-invariants` for the two-ended constants.

## Env (`SLOPDESK_*`)

Not exhaustive — grep `SLOPDESK_`. **Default idiom:** `!= "0"` → default-ON; `== "1"` → default-OFF; check the call site.

| `SLOPDESK_AUDIO` | host app-audio stream gate (default-ON); `_CODEC=pcm` bypasses AAC-ELD |
| `SLOPDESK_AUDIO_CODEC` / `_BITRATE` | read in `slopdesk-video`'s `audio_source`, NOT in Swift — the sender asks `slopdesk_audio_wire_format()` / `slopdesk_audio_bitrate_bps()`. Only the exact word `pcm` picks the codec-free arm (an unknown value is not a codec, so it stays AAC-ELD); the bitrate is CLAMPED to 32–320 kbps, default 128, and a typo parses to nothing rather than to zero. the `video-audio-row` invariant (`make lint-invariants`) bans either name under `Sources` — a Swift `ProcessInfo` read would be a second clamp, and two clamps that must agree cannot be tested for |

Documented as a byte-identical fallback and it was NOT: the inline path had no `keyframe` in scope, so it floored every frame at the delta pace floor — including a recovery IDR, whose delivery time IS the client's recovery time. Both paths now build one schedule (2026-08-22) |
| `SLOPDESK_PACE` | default-ON (`=0` disables). Chunk pacing on the send path |
| `SLOPDESK_PACE_US` | pins a STATIC inter-chunk gap in µs, for A/B against the adaptive one. An explicit value outranks `_PACE_ADAPTIVE` |
| `SLOPDESK_PACE_ADAPTIVE` | default-ON (`=0` reverts to the fixed gap). Derives the gap from the live ABR target rather than a constant |
| `SLOPDESK_PACE_RATE_X` | pace at this MULTIPLE of the live ABR target, default 2.5. TUNING, not a toggle |
| `SLOPDESK_KF_DUP` / `_KF_DUP_LOSS` | default-ON. Duplicates a keyframe's chunks above a loss threshold; the threshold is its own variable because the FEC tier is default-OFF, so gating on the tier alone would leave the default config always-dupping |
| `SLOPDESK_IDR_TOKENS` / `_IDR_REFILL_MS` / `_IDR_GRACE_MS` | the recovery-keyframe policy's three tunables, all TUNING rather than toggles — the token bucket's capacity (clamp 1–4), the ms per refilled token (clamp 100–5000, default 500 = the old sent-keyed spacing) and a PIN that sets the in-flight grace floor and ceiling to the same value for an A/B (clamp 0–1000 ms; unset leaves the adaptive `clamp(0.75×smoothedRTT, 40, 250)`). A text that will not parse leaves ONLY its own field at the default. Read through `EnvConfig`, so the `[env]` row above applies; until 2026-08-27 this was the host's last raw `ProcessInfo` read and a `config.toml` entry for any of the three did nothing |
| `SLOPDESK_NACK` / `_NACK_RING_FRAMES` | default-OFF (`=1`). Selective-ARQ retransmit; needs host AND client deployed together. The ring holds 96 frames by default |
| `SLOPDESK_ADAPTIVE_FEC_M` | the adaptive-FEC parity count. `m >= 2` is a THRESHOLD, not a bound: it changes the parity per group on the wire and selects the true [k + m, k] code over the XOR-equivalent default |
| `SLOPDESK_SUB_LAG_BYTES` | laggard-eviction threshold, default **32 MiB** — deliberately BELOW the 64 MiB offline gate. TUNING, not a toggle. A lone subscriber is never evicted because eviction needs two or more members |
| `SLOPDESK_SUPERD_SOCKET` | points hostd at a superd other than the login session's. **Every test that opens a pane must set it**, or it drives the developer's live custodian and a stray `release` ends somebody's running agent. `SuperdFixture` (host tests) and `startPrivateSuperd` (E2E) each boot a private daemon and set it. Read by BOTH ends — it is where superd `bind`s as well as where a client `connect`s — so a fixture must state the DAEMON's copy explicitly rather than let it inherit the test process's, which between fixtures deliberately points at a path nothing binds |
| `SLOPDESK_AGENT_CONTROL` | `=1` makes hostd CLAIM the agent-ctl listener. Default-OFF (writing to PTYs and spawning shells is not enabled silently). superd binds that socket either way and knows nothing about this flag — what it decides is whether hostd `listen`s for the `control` kind, and an unclaimed listener is never advertised into a spawned child's env, so off still means no `SLOPDESK_CONTROL_SOCKET` reaches a child (`docs/51` §6.6). The hook listener has NO flag, deliberately (`DECISIONS.md` 2026-07-29) |
| `SLOPDESK_SCREEND_SOCKET` | where `slopdesk-screend` binds and `ScreenClient` connects, default `$TMPDIR/slopdesk-screend.sock`. Read by BOTH ends, like superd's. The Swift client resolves it PER CALL rather than at construction: `ScreenClient.shared` is a `static let`, so capturing the address would freeze whatever the first toucher saw — in a test run, whichever suite sorts first, before `ScreendFixture` has aimed it at the private engine |
| `SLOPDESK_SCREEND_BIN` | which `slopdesk-screend` the client starts when none is listening, and which one `ScreendFixture` uses. Absent → the installed copy, then the cargo target dirs found by walking UP from the running executable — a SEARCH, not a fixed depth, because `.build/debug` is a symlink to `.build/<triple>/debug` and a binary next to the test bundle therefore sits one level deeper than `swift run`'s. Deliberately no `PATH` search: screend is not a user-facing command |
| `SLOPDESK_SCREEND_IDLE_EXIT` | seconds `slopdesk-screend` stays up holding NO connection before exiting, default 120, `0` = never (what the LaunchAgent sets, since launchd owns that copy). Read by screend itself, not by the Swift client. This is what stops `swift test --parallel` — one private engine per worker process — from leaving daemons behind (`docs/52`) |
| `SLOPDESK_FILE_TRANSFER` | `0` turns PATH 4 off entirely — hostd starts no `slopdesk-dropd` and nothing listens on `terminalPort + 2`. Default ON. Read by hostd, and it is the only PATH-4 switch: there is no toggle for the drop UI, which simply fails to connect |
| `SLOPDESK_FILE_DROP_DIR` | where uploads land, default `~/Downloads`. A leading `~`/`~/` is expanded against the DAEMON user's home, not the caller's. hostd resolves it and passes the absolute path on dropd's argv, so the child never re-reads the variable |
| `SLOPDESK_DROPD_BIN` | which `slopdesk-dropd` hostd spawns, and which one `DropdE2ETests` dials. Absent → the installed copy, then the cargo target dirs found by walking UP from the running executable, same search as `SLOPDESK_SCREEND_BIN` and for the same `.build/debug`-is-a-symlink reason |
| `SLOPDESK_SUPERD_DIR` | superd's own: relocates the whole socket directory (control + hook + agent-control + lock). Read once at startup, never per call — a daemon that answered "where is the hook socket?" differently at minute 40 than at minute 0 would hand two children two different addresses, which is `docs/51` §1 wearing a different hat |
| `SLOPDESK_PANE_RING_BYTES` | per-pane output retention in superd, default **4 MiB** — roughly a minute of a full-tilt build, sized for a restart rather than for history. `0` is honoured and means "retain nothing": the offsets still advance, so a returning hostd is told truthfully that what it missed is gone, instead of being handed a silent splice. TUNING, not a toggle |
| `SLOPDESK_WORKSPACE_STATE_DIR` | relocates `workspace-state.json`. EVERY `HostServer` builds a `HostWorkspaceStore` — a test that calls `start()` must set this or inject `workspaceStore:`, or it reads/overwrites the developer's real workspace |
| `SLOPDESK_ADB_BIN` / `_ANDROID_EMULATOR_BIN` / `_ANDROID_SERVER_JAR` / `_ANDROID_EMULATOR_ARGS` | Android panel tool overrides. No `adb` ⇒ the tab is `unavailable`; a missing `emulator` or jar is NOT (a plugged-in phone still lists, and a host with no jar still boots AVDs — it just cannot mirror). `adb` and the jar are vendored (below); the **emulator is deliberately not** — it comes from `sdkmanager` and is useless without gigabyte system images behind a licence accept. Detail: `docs/48-android-panel.md` |
| `SLOPDESK_ANDROID_HW` | `=1` arms `rust/slopdesk-androidd/tests/hardware.rs` (needs a booted device). Set by `slopdesk-gate android`; off ⇒ every case prints why it proved nothing and passes — Rust has no `XCTSkip`, and a silent pass is indistinguishable from a gate that ran and proved nothing |
| `SLOPDESK_HOSTD_BIN` | **No reader.** It named the binary the menu-bar app spawned, and `docs/60` deleted the app — hostd is controlled entirely by CLI. There are two ways to start one now and neither consults a variable: `slopdesk-ops install hostd` writes a `LaunchAgent` naming the copy it installed under `~/Library/Application Support/SlopDesk/bin/`, and `slopdesk-ops restart-hostd` replays a recorded launch path. The row stays because the variable's ABSENCE is the claim: a search order for hostd would be a second one beside the installer's, and there is nothing left to search from |
| `SLOPDESK_INSPECTORD_BIN` | which `slopdesk-inspectord` hostd spawns. Absent → the installed copy, then the cargo target dirs found by walking UP from the running executable, same search as `SLOPDESK_DROPD_BIN`. There is no separate on/off switch: hostd's `--inspector` flag decides whether PATH 3 comes up at all, and `--transcript` names the file the daemon follows |
| `SLOPDESK_ANDROIDD_BIN` | which `slopdesk-androidd` hostd spawns. Absent → the installed copy, then the cargo target dirs found by walking UP from the running executable, same search as `SLOPDESK_DROPD_BIN` |
| `SLOPDESK_PROBE_BIN` / `_CODESEED_BIN` / `_AGENTHOOKS_BIN` | which `slopdesk-probe` (the metadata RPC's git/directory/session half), `slopdesk-codeseed` (the code panel's workbench profile) and `slopdesk-agenthooks` (the Claude Code hooks installer) hostd forks. The probe and the installer are ROOT-workspace binaries, so their cargo target dir is `rust/target/` and not the per-crate one `RustServicePaths` walks for: absent, they resolve BESIDE the running host executable, where `make build` stages them. The seeder has its own workspace and takes the ordinary `RustServicePaths` walk. A missing probe costs the git line and the file tree and nothing else; a missing seeder makes the code panel `unavailable`; a missing installer reports the hooks NOT installed and refuses to install them |
| `SLOPDESK_CODE_SERVER_BIN` | Code panel binary override, and the escape hatch that outranks the pin (bisecting a candidate build). Unset ⇒ the `locate_tool` walk described under **Vendored runtime deps** below |
| `SLOPDESK_BUILD_HASH` | Read at RUNTIME by `slopdesk version` (`CLIVersion.swift`) — appends a short build hash in parentheses. Absent in a plain `swift build`, so the parenthetical simply vanishes |
| `SLOPDESK_VERSION` / `_BUILD_NUMBER` / `_SIGN_IDENTITY` / `_NOTARY_PROFILE` / `_SKIP_NOTARIZE` | `slopdesk-release package` only — never read by shipped code. `_VERSION` is required and must match the `CLIVersion.version` constant or the script refuses to package. `_SKIP_NOTARIZE=1` is a pipeline dry-run: the output is signed but will NOT pass Gatekeeper elsewhere. Detail: `docs/49-release-pipeline.md` |

Deleted deliberately — do not reintroduce: `SLOPDESK_WORKSPACE_DOC`, `SLOPDESK_PANE_FANOUT` (multi-client sync is unconditional; a host that refuses `channelClass 1` gives a client a blank window with no error).

## Vendored runtime deps

The right panel's surfaces stand on programs this repo does not build. They are **pinned by URL + SHA-256 in `ThirdParty/tools/tools.lock`** and provisioned by `rust/slopdesk-provision` (`make provision`, `make provision-check`) into `ThirdParty/tools/.prefix/bin` (gitignored, ~730 MB). Same bargain as `ThirdParty/ghostty/`: the recipe is committed, the artifact is not.

**Why.** Homebrew's `code-server` formula froze at 4.112 and was deprecated, and nothing in the repo recorded — or could enforce — the version the panel was written against. The panel sat on Code 1.112 for months, below the 1.121 floor where the built-in mermaid preview landed, and no gate could see it.

| Dep | Surface | Pinned | Note |
|---|---|---|---|
| `code-server` | code panel (verb 18) | 4.131.0 | floor is **4.121** — Code 1.121 is where `mermaid-markdown-features` became built-in |
| `baguette` | simulator panel (verb 21) | 0.1.88 | executable is `Baguette`, sibling to the `.bundle` it loads assets from; the `bin/` symlink was checked to still resolve it |
| `adb` | Android panel (verb 22) | 37.0.1 | Google's versioned zip; its `repository2-3.xml` SHA-1 was cross-checked against our SHA-256 |
| `scrcpy-server` | Android panel | 4.1 | **committed** at `ThirdParty/tools/vendor/scrcpy-server` (716 KB, not an executable — the device's `app_process` runs it). `slopdesk-provision` verifies those bytes, never downloads them |

**Search order** (`locate_tool` in `rust/slopdesk-androidd/src/toolchain.rs`, reached from Swift through `slopdesk_host_service_binary` — there is no second copy to mirror, and the wording that used to name a Swift `searchDirectories` as the canonical one is why the two drifted: `FileManager.isExecutableFile` is `access(X_OK)`, which is TRUE for a directory, so a directory wearing a tool's name on `PATH` reached `posix_spawn`. The crate tests `is_file()` and the mode bits and walks past it. The Swift `AndroidToolchain` that used to hold the other copy is on the must-stay-deleted list in the row above): `SLOPDESK_*_BIN` override → **vendored prefix** → `PATH` → `~/.local/bin` → `/opt/homebrew/bin` → `/usr/local/bin`. The prefix outranking `PATH` is deliberate and is the whole point: a stale Homebrew copy silently winning is the failure this layer ends. `VendoredTools` finds the prefix by walking up from the running binary looking for `tools.lock`, so a hostd copied out of the checkout correctly resolves nothing and falls through.

**hostd never provisions.** Nothing on the runtime path downloads, extracts or writes — it stats. A coding host must not reach the network because someone opened a panel.

**Not vendorable, and not attempted:** iOS simulator runtimes and `simctl` (inside Xcode, Apple's licence — `baguette` is the vendorable half), and the Android emulator with its system images (`sdkmanager`, licence-gated, gigabytes per API level — `adb` is the vendorable half). Both keep their existing host-discovery path and report unavailable when the host has none.

**Bumping a pin has a tail.** For `code-server` specifically: re-measure `CodePanelPresentation.clippedTitleBarHeight` against the new workbench (the title bar the client clips off — 35px on Code 1.112, 30px on 1.131; it is inline geometry, not a greppable CSS constant, so measure `getBoundingClientRect()` on `#workbench.parts.titlebar`), re-check `slopdesk-codeseed`'s `resources/settings.json` against the new settings schema (only registered keys may be seeded, and the shipped extension set moves between releases), and run `slopdesk-ops measure-code-server` — the daemon prewarms this child at boot (docs/DECISIONS 2026-08-07), so a spawn→listen regression lands on every hostd restart, not just on panel opens.

## Wire golden vectors — the long version

Manual binary encode (no JSON/Codable on the hot path); multi-byte ints big-endian; UUIDs 16 raw bytes. After wire changes run `slopdesk-gate golden`, then update `docs/20-wire-protocol.md`.

**Never** `>`-redirect the generator over `golden/golden_vectors.json` — it emits a subset (13 frozen keys are XCTest-only). Generate with **no** `SLOPDESK_*` env set. An intended format change is a surgical hand-merge, not a regeneration.
